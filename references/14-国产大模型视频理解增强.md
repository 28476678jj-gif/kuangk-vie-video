# 14 · 国产大模型视频理解增强

Kimi、混元 Hy4、Bunny 这类模型看整段视频的能力比不上闭源大模型的原生视频输入，直接把 mp4 丢过去，拿回来的常常是一句笼统描述，时间码全靠编。这份模块的做法是别让模型直接啃视频，先把视频拆成它吃得下的包。

## 四层信息，逐层补齐

模型的短板不一样，缺哪层就补哪层。

**第一层 元数据。** 时长、帧率、分辨率、有没有音轨、编码格式。用 ffprobe 一次性拿准。模型拿到这几项之后不会再把 3 分钟的片子说成 5 分钟，也不会对 1920×1080 的片子给出竖屏构图建议。这一层的成本几乎为零，收益最大。

**第二层 镜头。** 用 ffmpeg 的场景检测找出切点，切成一张分镜表，每行一个镜头，带起止时间码和一张代表帧。模型靠这张表建立全局结构，知道片子分几段、每段多长。没有这一层，模型描述长片时会把前后镜头混在一起。

**第三层 帧。** 每个镜头抽 1 到 3 帧，另加一组全局均匀采样帧。每帧文件名里带时间码，模型引用时能对应回去。帧数按模型的图片上限来定，超了会被截断或者被拒。

**第四层 文字。** 画面上的字（字幕、标题、数据）和音频里的话。模型读小字普遍不准，先 OCR 出来塞进包里；音频转录后按时间码对齐到镜头。这两项补上之后，模型对"这段在讲什么"的判断会明显变稳。OCR 有两个后端可选，`rapidocr-onnxruntime`（pip 装，中文效果好，不需要管理员权限，优先用）和 tesseract（系统装）。两个都不在场就跳过并在 manifest 里标注 `ocr_backend: none`，脚本不硬失败。

## 提示策略

结构化输入配结构化输出。给模型一份 manifest.json，同时要求它按 schema 回，不要让它自由发挥。

- 要求每个判断都带时间码。模型没给时间码的结论，当作没来源，直接打回重问。
- 分两轮。第一轮只给分镜表和元数据，让它说清楚片子结构和每段在干什么；第二轮再给指定镜头的帧图，让它补细节。一次性全塞进去，长片的中间段通常会被忽略。
- 输出 schema 写在提示里，字段固定（镜号、起止、画面内容、出现的文字、可提炼的点、对应口播）。回传 JSON，别让它写散文。

## 降级策略

模型能力不够时按这个顺序退，不要直接放弃。

1. 模型不接受图片。只发 manifest.json 和分镜表的文本，让它基于时间码和结构做分析。精度下降但能用。
2. 模型图片数量受限。把全局帧降到 8 到 12 帧，每帧缩到长边 768，保留时间码。细节会丢，结构还在。
3. 模型上下文短。分片处理，一次只喂相邻的几个镜头，最后用一轮做汇总。

## 跑起来

支持两个 OCR 后端，`rapidocr-onnxruntime`（pip 装，优先）和 tesseract（系统装，需管理员权限）。装之前先看本机能不能提权，装不了就用 rapidocr：

```sh
pip install rapidocr-onnxruntime
python scripts/vision/vid2pack.py --video 参考.mp4 --out 拆解包/ --model hy4
```

产出四样：`manifest.json`（机器读）、`分镜表.md`（人和模型都能读）、`frames/`（带时间码的关键帧）、`prompt_pack.md`（可直接粘贴的提示脚手架，已按 `--model` 调好帧数和字段）。

与 `01-拆解.md` 的分工：那份讲怎么从参考片里学机制用于复刻，这份讲怎么让国产模型把片子看准。两条路共用 `vid2pack.py` 的输出。
